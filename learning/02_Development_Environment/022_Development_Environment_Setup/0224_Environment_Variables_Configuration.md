# 第4章 環境変数と設定管理：コードと設定を分離せよ

## 🎯 この章で学ぶこと
- なぜAPIキーやデータベースのパスワードをソースコードに直接書いてはいけないのか（ハードコーディングの危険性）を説明できる。
- 「環境変数」を使って、アプリケーションの振る舞いを外部から変更する方法を理解する。
- `.env`ファイルと`dotenv`のようなライブラリを使い、開発環境での設定を管理する方法を説明できる。
- JSONやYAMLといった設定ファイルの使い分けと、それぞれの特徴を理解する。
- 本番環境、開発環境、テスト環境で設定を切り替える必要性を説明できる。

## 🤔 なぜ重要なのか
あなたが開発中のWebアプリケーションは、外部の天気予報APIに接続して情報を取得します。接続には、あなた専用の「APIキー」が必要です。このAPIキーを、ソースコードの中に直接書き込んでしまいました。

`const API_KEY = "super-secret-api-key-12345";`

そして、このコードをGitHubの**パブリックリポジトリ**にプッシュしてしまいました。数時間後、あなたのアカウントにはAPIの利用料として100万円の請求が...。悪意のある第三者があなたのAPIキーを悪用したのです。

これは極端な例ですが、**設定情報（特にパスワードやAPIキーなどの機密情報）をソースコードに直接書き込む（ハードコーディングする）こと**は、最も避けるべき習慣の一つです。なぜなら、
1.  **セキュリティリスク**: ソースコードが漏洩した場合、機密情報がすべて流出する。
2.  **柔軟性の欠如**: データベースの接続先やAPIキーが変わるたびに、コードを修正して再デプロイする必要がある。
3.  **環境ごとの差異**: 開発環境（自分のPC）と本番環境（ユーザーが使うサーバー）では、データベースの接続先などが異なります。コードが同じなのに、動かす場所によって設定を変えたい、という要求に応えられません。

**環境変数**と**設定ファイル**は、このような「コード」と「設定」を綺麗に分離するための基本的な技術です。これにより、アプリケーションの安全性と柔軟性が劇的に向上します。

## 📚 基礎概念の理解

### 環境変数 (Environment Variables)
OSレベルで保持される、キーと値のペアからなる変数です。アプリケーションは起動時にOSからこれらの変数を読み取り、動作を変化させることができます。

-   **役割**: アプリケーションの外部から、その振る舞いを制御する。
-   **例**:
    -   `PORT=8080`: アプリケーションが待ち受けるポート番号を指定する。
    -   `NODE_ENV=production`: アプリケーションを本番モードで起動させる。
    -   `DATABASE_URL=postgres://user:password@host:port/db`: データベースの接続情報を渡す。
-   **特徴**:
    -   ソースコードには一切触れずに、設定を変更できる。
    -   サーバーの管理者が設定値を管理するため、開発者は本番環境のパスワードを知る必要がない。

### 設定ファイル (Configuration Files)
環境変数だけでは管理が煩雑になるような、複雑な設定情報を記述するためのファイルです。

-   **種類**:
    -   **`.env`ファイル**: 環境変数を手軽に管理するためのファイル。`キー=値`の形式で記述する。`dotenv` (Node.js) や `python-dotenv` (Python) といったライブラリと組み合わせて使う。**開発環境での利用が主目的**。
    -   **JSON (`config.json`)**: JavaScriptとの親和性が高い。データ構造を厳密に記述できる。コメントが書けないのが欠点。
    -   **YAML (`config.yaml`)**: 人間にとって読み書きしやすい。コメントも書ける。インデント（字下げ）で階層構造を表現する。

```yaml
# config.yaml の例
database:
  host: localhost
  port: 5432
  user: "dev_user"
  # パスワードは直接書かず、環境変数から参照するのが望ましい
  password: "${DB_PASSWORD}" 

api:
  weather_api_key: "${WEATHER_API_KEY}"
```

### 機密情報（クレデンシャル）の扱い
APIキー、パスワード、証明書などの機密情報は、特別な注意を払って管理する必要があります。

-   **絶対的なルール**: **機密情報をGitリポジトリにコミットしないこと！**
-   **ベストプラクティス**:
    1.  開発環境では、`.env`ファイルに機密情報を記述する。
    2.  **.envファイルを必ず`.gitignore`に追記**し、Gitの管理対象から除外する。
    3.  リポジトリには、`.env.example`という名前のサンプルファイル（中身はダミーの値）をコミットし、どのような環境変数が必要かを他の開発者に伝える。
    4.  本番環境では、サーバーの環境変数機能や、AWS Secrets Manager, GCP Secret Manager, HashiCorp Vaultのような専門のシークレット管理サービスを利用して、安全に情報を注入する。

## 💡 実践的な活用

### ハンズオン：`.env`でNode.jsアプリの設定を管理する
`dotenv`ライブラリを使って、ポート番号と表示メッセージを外部から変更できる簡単なWebサーバーを作成します。

**準備**:
1.  `npm init -y`でプロジェクトを初期化する。
2.  `npm install express dotenv`で必要なパッケージをインストールする。

**手順**:
1.  **`.env`ファイルを作成** (Gitにはコミットしない！)
    ```
    PORT=3000
    GREETING="Hello from .env file!"
    ```

2.  **`.gitignore`ファイルを作成**
    ```
    node_modules/
    .env
    ```

3.  **アプリケーション本体 (`app.js`) を作成**
    ```javascript
    // 1. dotenvを設定。これにより、.envファイルの内容がprocess.envに読み込まれる
    require('dotenv').config();
    const express = require('express');

    const app = express();
    
    // 2. 環境変数から値を取得。なければデフォルト値を使う
    const port = process.env.PORT || 8080;
    const greeting = process.env.GREETING || "Hello, World!";

    app.get('/', (req, res) => {
      res.send(greeting);
    });

    app.listen(port, () => {
      console.log(`Server running at http://localhost:${port}`);
    });
    ```
**実行**:
-   `node app.js`で起動すると、`.env`ファイルが読み込まれ、「Server running at http://localhost:3000」と表示され、ブラウザでアクセスすると「Hello from .env file!」と表示されます。
-   `.env`ファイルを削除またはリネームしてから`node app.js`で起動すると、デフォルト値が使われ、「Server running at http://localhost:8080」と表示され、「Hello, World!」と返します。

このように、コードを変更せずにアプリケーションの動作を変えることができました。

## 🔍 深掘り：プロの視点

### 設定の読み込み優先順位
プロフェッショナルなアプリケーションでは、柔軟性を高めるために複数の方法で設定を読み込めるようにし、明確な優先順位を設けるのが一般的です。

**高い 優先度 ← 低い**
`OSの環境変数` > `.env`ファイル > `config.json/yaml` > `コード内のデフォルト値`

この順序により、
- 普段は`config.json`やデフォルト値で動く。
- 開発者は自分のPCでだけ`.env`ファイルを使って設定を上書きできる。
- 本番サーバーでは、運用者がOSの環境変数を設定するだけで、すべての設定に優先して値を注入できる。
といった柔軟な運用が可能になります。

### クラウドネイティブな設定管理
現代のクラウドベースの開発では、シークレット管理はさらに重要性を増します。コンテナ化されたアプリケーションが複数の環境で動くのが当たり前だからです。

-   **シークレット管理サービス (AWS Secrets Manager, GCP Secret Managerなど)**:
    -   機密情報を暗号化して安全に保管する専用サービス。
    -   IAMロールなどを使って、特定のアプリケーション（コンテナ）だけに、実行時に動的にシークレットへのアクセス権を付与できる。
    -   シークレットのローテーション（定期的な自動更新）機能など、高度なセキュリティ機能を持つ。

-   **なぜ必要か？**:
    サーバーに環境変数として直接設定するのは手軽ですが、誰がそのサーバーにアクセスできるのか、誰が値を見られるのか、といったアクセス制御が煩雑になりがちです。専用のシークレット管理サービスを使うことで、これらの問題を解決し、より堅牢なセキュリティ体制を築くことができます。

## 📋 まとめとチェックポイント
- セキュリティと柔軟性のために、「コード」と「設定」は必ず分離する。
- APIキーやパスワードなどの機密情報をソースコードにハードコーディングしてはならない。
- 環境変数は、アプリケーションの振る舞いを外部から動的に変更するためのOSの仕組みである。
- `.env`ファイルは、開発環境での環境変数管理を容易にするための便利な仕組み。
- `.env`ファイルや機密情報を含む可能性のある設定ファイルを`.gitignore`に登録し、絶対にGitで管理しない。
- 複数の設定方法を組み合わせる際は、明確な優先順位を設けることが重要である。
