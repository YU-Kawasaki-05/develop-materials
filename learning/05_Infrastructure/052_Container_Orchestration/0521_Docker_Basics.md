# Docker基礎：コンテナ技術が変えた開発の常識

## 🎯 この章で学ぶこと
- 「コンテナ」がなぜ生まれたのか、従来の仮想マシンとの違いを明確に説明できるようになる。
- Dockerの3大基本要素「Dockerfile」「Image」「Container」の関係性を理解する。
- `docker build`, `docker run`, `docker ps`, `docker exec` といった基本的なDockerコマンドを使いこなせるようになる。
- シンプルなWebアプリケーションをコンテナ化するためのDockerfileを作成できるようになる。
- 「Immutable Infrastructure（不変のインフラ）」というコンテナ時代の重要な概念を理解する。

## 🤔 なぜ重要なのか
「自分のパソコンでは動いたのに、本番サーバーでは動かない…」これは、古くから開発者を悩ませてきた悪夢のような問題です。OSの違い、ライブラリのバージョンの違い、環境変数の設定ミスなど、原因は様々です。この「環境差異」の問題を根本的に解決し、現代のソフトウェア開発に革命をもたらしたのが**Docker**に代表される**コンテナ技術**です。

Dockerは、アプリケーションをその実行に必要な全てのライブラリや設定ファイルごと、ひとまとめにして「コンテナ」という箱に入れてしまいます。この箱は、開発者のPC、テストサーバー、本番環境など、どこに持っていっても全く同じように動作します。

例えるなら、海外旅行に行く際に、日本の電化製品を現地のコンセントでそのまま使えるようにする「変換プラグ付きの万能電源タップ（コンテナ）」のようなものです。このタップさえあれば、国（環境）が変わっても、いつも通りドライヤー（アプリケーション）を使えます。

この「どこでも同じように動く」という特性は、開発の効率化、デプロイの高速化、そしてマイクロサービスアーキテクチャの実現に不可欠な基盤です。AIに開発を依頼する際も、成果物をDockerコンテナとして受け取ることは、もはや常識となっています。Dockerを理解することは、現代のWebエンジニアにとっての「読み書きそろばん」に等しい必須スキルなのです。

## 📚 基礎概念の理解

### コンテナ vs 仮想マシン(VM)
コンテナ技術を理解するために、よく比較されるのが従来の仮想マシン（VM）です。

- **仮想マシン (Virtual Machine)**:
    - **仕組み**: ホストOSの上に、ハイパーバイザーというソフトウェアを介して、**ゲストOSを丸ごと**起動します。そのゲストOS上でアプリケーションを動かします。
    - **例え**: 家（ホストOS）の中に、完全な生活設備（キッチン、バス、トイレ）を備えたもう一軒の家（ゲストOS）を建てるようなもの。
    - **長所**: 高い分離性。ゲストOSはホストOSから完全に独立しています。
    - **短所**: ゲストOSを丸ごと起動するため、起動が遅く、メモリやディスクの消費量が非常に大きい。

- **コンテナ (Container)**:
    - **仕組み**: ホストOSのカーネル（OSの中核部分）を共有し、プロセスやファイルシステムだけを隔離します。ゲストOSは存在しません。
    - **例え**: 家（ホストOS）の中に、壁（隔離技術）で仕切られた個別の部屋（コンテナ）を作るようなもの。キッチンやバスなどの設備（OSカーネル）は共有します。
    - **長所**: ゲストOSがないため、起動が非常に高速（数秒）で、軽量。リソース消費が少ない。
    - **短所**: VMほどの強い分離性はありません（ただし、実用上は十分安全です）。

### Dockerの3大要素：Dockerfile, Image, Container
Dockerを扱う上で、この3つの関係を理解することが最も重要です。

1.  **Dockerfile**:
    -   **概念**: コンテナの**設計図**。テキストファイルであり、「どのOSイメージを土台にするか」「どのファイルをコピーするか」「どのコマンドを実行するか」といった、コンテナの構成情報を記述します。
    -   **役割**: これから作成するDockerイメージの内容を定義します。

2.  **Image (イメージ)**:
    -   **概念**: Dockerfileを元に作成された、アプリケーションとその実行環境をひとまとめにした**静的なテンプレート**。一度ビルドしたら変更されない「読み取り専用」のファイルです。
    -   **役割**: このイメージを元に、コンテナを何個でも作成することができます。Docker Hubなどのレジストリサービスを通じて、チーム内での共有や公開が可能です。

3.  **Container (コンテナ)**:
    -   **概念**: Dockerイメージを元に起動された、**実行中のインスタンス**。実際にアプリケーションが動作している「動的な」状態のものです。
    -   **役割**: アプリケーションのプロセスを隔離された環境で実行します。

**料理の例え**:
- `Dockerfile`: ピザのレシピ（手順書）
- `Image`: レシピ通りに調理され、箱詰めされた冷凍ピザ
- `Container`: 冷凍ピザをオーブンで温めて、食べられる状態にしたもの

## 💡 実践的な活用

### 基本的なDockerコマンド
- `docker build -t <イメージ名>:<タグ> .`
    - カレントディレクトリにある`Dockerfile`を元に、Dockerイメージをビルド（作成）します。`-t`オプションで名前とタグ（バージョン情報）を付けます。
- `docker images`
    - ローカルに存在するDockerイメージの一覧を表示します。
- `docker run [オプション] <イメージ名>:<タグ>`
    - 指定したイメージからコンテナを起動します。よく使うオプション:
        - `-d`: バックグラウンドで実行（デタッチモード）
        - `-p <ホスト側ポート>:<コンテナ側ポート>`: ポートフォワーディング（例: `-p 8080:80` は、ホストの8080番ポートへのアクセスをコンテナの80番ポートに転送）
        - `--name <コンテナ名>`: コンテナに名前を付ける。
- `docker ps`
    - 現在実行中のコンテナ一覧を表示します。`-a`オプションを付けると、停止中のコンテナも表示されます。
- `docker stop <コンテナID or コンテナ名>`
    - 実行中のコンテナを停止します。
- `docker rm <コンテナID or コンテナ名>`
    - 停止中のコンテナを削除します。
- `docker exec -it <コンテナID or コンテナ名> /bin/bash`
    - 実行中のコンテナの中に入って、インタラクティブなシェル操作を行います。デバッグに非常に便利です。

### ハンズオン：シンプルなWebサーバーをコンテナ化する
- **課題**: "Hello, Docker!" と表示するだけのシンプルなNode.jsのWebサーバーを、Dockerコンテナとして実行します。
- **手順**:
    1.  **アプリケーションコードの作成 (`app.js`)**
        ```javascript
        const http = require('http');
        const server = http.createServer((req, res) => {
          res.writeHead(200, { 'Content-Type': 'text/plain' });
          res.end('Hello, Docker!\n');
        });
        server.listen(80, '0.0.0.0');
        console.log('Server running at http://0.0.0.0:80/');
        ```
    2.  **Dockerfileの作成 (`Dockerfile`)**
        ```dockerfile
        # 1. ベースイメージの指定
        FROM node:18-alpine

        # 2. 作業ディレクトリの作成と設定
        WORKDIR /app

        # 3. アプリケーションのコードをコピー
        COPY app.js .

        # 4. コンテナがリッスンするポートを指定
        EXPOSE 80

        # 5. コンテナ起動時に実行するコマンド
        CMD ["node", "app.js"]
        ```
    3.  **ビルド＆実行**
        ```bash
        # イメージをビルド
        docker build -t my-node-app:1.0 .

        # コンテナを起動
        docker run -d -p 8080:80 --name my-web-server my-node-app:1.0
        ```
- **期待される結果**: ブラウザで `http://localhost:8080` にアクセスすると、"Hello, Docker!" と表示されます。自分のPCにNode.jsがインストールされていなくても、Dockerさえあれば実行できるのがポイントです。

## 🔍 深掘り：プロの視点

### Immutable Infrastructure (不変のインフラ)
コンテナ時代において非常に重要な設計思想です。
- **概念**: 一度作成したコンテナ（インフラ）は、実行中に変更（パッチ適用、設定変更など）しない。変更が必要な場合は、新しいバージョンのイメージをビルドし、古いコンテナを破棄して新しいコンテナに置き換える。
- **なぜ重要か**:
    - **予測可能性**: 実行中の環境に手動変更が加わらないため、「開発環境と本番環境の差異」といった問題が起こり得ません。
    - **簡単なロールバック**: 新しいバージョンに問題があれば、古いバージョンのイメージを使ってコンテナを再起動するだけで、即座に以前の状態に戻せます。
    - **構成管理の簡素化**: インフラの状態はDockerfileというコードで完全に管理されるため、再現性が極めて高くなります。

### レイヤー構造とキャッシュ
`Dockerfile`の各命令（`FROM`, `COPY`, `RUN`など）は、イメージ内でそれぞれ「レイヤー」と呼ばれる層を形成します。Dockerはイメージをビルドする際、このレイヤー構造を巧みに利用してキャッシュを効かせます。
- **仕組み**: `Dockerfile`の上から順にビルドし、途中の行に変更がなければ、そのレイヤーまでは前回のビルド結果（キャッシュ）を再利用します。
- **最適化**: 変更頻度の低い命令（ベースイメージの指定やライブラリのインストールなど）を`Dockerfile`の前半に、変更頻度の高い命令（アプリケーションコードのコピーなど）を後半に配置することで、ビルド時間を大幅に短縮できます。

## 📋 まとめとチェックポイント
- コンテナは、ゲストOSを必要とせず、軽量・高速に動作する仮想化技術。
- `Dockerfile` (設計図) → `docker build` → `Image` (静的テンプレート) → `docker run` → `Container` (実行インスタンス) という関係性を理解する。
- 基本的なDockerコマンドは、コンテナ化されたアプリケーションを開発・実行するための必須ツール。
- コンテナ化の最大の利点は「どこでも同じように動く」ことであり、環境差異の問題を解決する。
- **Immutable Infrastructure**は、コンテナのメリットを最大限に活かすための重要な設計思想。
