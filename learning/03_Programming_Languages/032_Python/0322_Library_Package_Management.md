# 0322 ライブラリとパッケージ管理

## 🎯 この章で学ぶこと
- Pythonの「ライブラリ（パッケージ）」が、開発効率を飛躍的に向上させる理由を理解する。
- `pip`コマンドを使い、PyPI (Python Package Index) からサードパーティ製ライブラリをインストール、アップグレード、アンインストールできるようになる。
- `requirements.txt`ファイルを用いて、プロジェクトの依存関係を管理し、他の開発者と環境を共有する方法を習得する。
- 複数のプロジェクトで異なるバージョンのライブラリを使い分けるために「仮想環境 (`venv`)」がなぜ不可欠なのかを説明できる。
- `venv`を使って仮想環境を作成・有効化し、その中でパッケージを管理する一連の流れを実践できる。

## 🤔 なぜ重要なのか
プログラミングとは、しばしば「車輪の再発明をしない」ことに例えられます。複雑な数学計算、Webサーバーの構築、Excelファイルの操作など、多くの一般的な機能は、既に誰かが高品質なコードとして作成し、**ライブラリ**として公開してくれています。Pythonの真の力は、この巨大で活発なライブラリ生態系にあると言っても過言ではありません。

しかし、複数のプロジェクトに関わると、次のような問題に直面します。
- プロジェクトAではライブラリXのバージョン1.0が必要だが、プロジェクトBではバージョン2.0が必要。
- 自分のPCでは動くのに、同僚のPCでは「ライブラリがない」というエラーで動かない。

これらの問題を解決するのが、**パッケージ管理**と**仮想環境**の役割です。適切にパッケージを管理し、プロジェクトごとに環境を分離するスキルは、クリーンで再現性の高い開発を行うための必須知識です。これができなければ、個人開発の域を超え、チームでの協業や本番環境へのデプロイは困難になります。

## 📚 基礎概念の理解

### ライブラリ、PyPI、pip
- **ライブラリ (Library) / パッケージ (Package)**: 特定の機能を提供する、再利用可能なPythonコードの集まり。ほぼ同義で使われます。標準で組み込まれている**標準ライブラリ**と、外部から追加する**サードパーティ製ライブラリ**があります。
- **PyPI (Python Package Index)**: サードパーティ製ライブラリが登録されている公式の巨大なリポジトリ。通称「チーズショップ」。世界中の開発者が作成した数十万ものパッケージがここに集まっています。
- **pip**: PyPIからパッケージをダウンロードし、インストールするための公式コマンドラインツール。Pythonをインストールすると、通常は一緒にインストールされます。

**基本的な`pip`コマンド**:
- `pip install <package_name>`: パッケージをインストールする。
- `pip install <package_name>==<version>`: バージョンを指定してインストールする。
- `pip install --upgrade <package_name>`: パッケージを最新版にアップグレードする。
- `pip uninstall <package_name>`: パッケージをアンインストールする。
- `pip list`: インストール済みのパッケージ一覧を表示する。

### 依存関係の管理: `requirements.txt`
プロジェクトがどのライブラリのどのバージョンに依存しているかを記録するための、ただのテキストファイルです。

**`requirements.txt`の例**:
```
requests==2.28.1
numpy>=1.20.0
pandas
```
- `==`: バージョンを厳密に指定。
- `>=`: 指定バージョン以上を許容。
- バージョン指定なし: 最新版をインストール。

**使い方**:
1.  **ファイルへの書き出し**:
    `pip freeze > requirements.txt`
    このコマンドは、現在環境にインストールされている全てのパッケージとその厳密なバージョンをファイルに出力します。

2.  **ファイルからのインストール**:
    `pip install -r requirements.txt`
    このコマンドは、ファイルに記載された全てのパッケージを指定されたバージョンで一括インストールします。これにより、他の開発者も全く同じ環境を簡単に再現できます。

### 環境の分離: 仮想環境 (`venv`)
仮想環境は、プロジェクトごとに独立したPython実行環境とライブラリを格納するための「砂場（サンドボックス）」のようなものです。

**なぜ必要か？**:
もし仮想環境を使わないと、全てのプロジェクトのライブラリがPCのグローバルな領域にインストールされてしまいます。
- **バージョンの衝突**: プロジェクトAが`lib-X v1.0`を、プロジェクトBが`lib-X v2.0`を必要とした場合、両立できません。
- **環境の汚染**: あるプロジェクトで使わなくなったライブラリが残り続け、`pip freeze`の結果が肥大化し、本当に必要な依存関係が分からなくなります。

**`venv`**は、Pythonに標準で付属している仮想環境管理ツールです。これにより、プロジェクトごとに完全に独立した環境を簡単に作成できます。

## 💡 実践的な活用

### ハンズオン：仮想環境を使ったプロジェクト設定
Webページの情報を取得する人気のライブラリ`requests`を使って、プロジェクトをセットアップしてみましょう。

1.  **プロジェクトフォルダと仮想環境の作成**:
    ```bash
    mkdir python-project && cd python-project
    python -m venv venv  # 'venv'という名前の仮想環境を作成
    ```
    `venv`という名前のフォルダが作成されます。これが仮想環境の実体です。

2.  **仮想環境の有効化（アクティベート）**:
    -   **Windows**:
        ```bash
        .\venv\Scripts\activate
        ```
    -   **macOS / Linux**:
        ```bash
        source venv/bin/activate
        ```
    成功すると、コマンドプロンプトの先頭に`(venv)`のように表示されます。これ以降、`python`や`pip`コマンドはこの仮想環境内のものを使うことになります。

3.  **ライブラリのインストール**:
    ```bash
    pip install requests
    ```

4.  **`requirements.txt`の作成**:
    ```bash
    pip freeze > requirements.txt
    ```
    ファイルの中身を確認すると、`requests`とその依存パッケージが記録されているはずです。

5.  **簡単なコードの実行 (`main.py`)**:
    ```python
    import requests

    try:
        response = requests.get("https://www.python.org")
        print(f"Status Code: {response.status_code}")
        # print(response.text[:200]) # 最初の200文字を表示
    except requests.exceptions.RequestException as e:
        print(f"An error occurred: {e}")
    ```
    `python main.py`で実行し、ステータスコード`200`が表示されれば成功です。

6.  **仮想環境の無効化（ディアクティベート）**:
    作業が終わったら、`deactivate`コマンドで仮想環境を抜けます。

この一連の流れが、Pythonでプロジェクトを始める際の基本作法となります。

## 🔍 深掘り：プロの視点

### `pip` vs `conda`
データサイエンスの分野では、`conda`という別のパッケージ・環境管理ツールがよく使われます。
- **`pip`**: Pythonパッケージ専門のマネージャー。
- **`conda`**: Pythonだけでなく、C/C++ライブラリやRなど、非Pythonの依存関係も管理できる。科学計算ライブラリはPython以外のコードに依存することが多いため、`conda`が好まれる傾向にあります。

Web開発など、Python中心のプロジェクトでは`pip`と`venv`の組み合わせが標準的です。データサイエンスや機械学習プロジェクトでは、`conda`の使用が一般的です。両者は役割が似ていますが、解決しようとしている問題のスコープが異なります。

### `package-lock.json`との比較
`requirements.txt`は、Node.jsの`package.json`に似ていますが、より単純です。
`pip freeze`で生成される`requirements.txt`は、依存ライブラリのさらにその依存ライブラリまで、全てのパッケージのバージョンを固定するため、Node.jsの`package-lock.json`の役割に近いです。

しかし、手動で`requirements.txt`を編集して`pandas>=1.0`のように柔軟な指定をすることもできます。このため、開発中は柔軟な指定をし、本番環境用には`pip freeze`でバージョンを完全固定したファイルを別途用意する、といった運用もよくなされます。より高度な依存関係管理ツールとして`Poetry`や`Pipenv`もあり、これらは`package.json`と`package-lock.json`のように、トップレベルの依存関係と、全ての依存関係を別々のファイルで管理するアプローチをとっています。

## 📋 まとめとチェックポイント
- Pythonの強力なエコシステムは、PyPIに登録された豊富なサードパーティ製ライブラリによって支えられている。
- `pip`はPyPIからライブラリをインストール・管理するための基本ツール。
- `requirements.txt`は、プロジェクトの依存ライブラリを定義し、環境の再現性を確保するためのファイル。
- 仮想環境 (`venv`) は、プロジェクトごとにライブラリを分離し、依存関係の衝突や汚染を防ぐための必須の仕組み。
- プロジェクトを開始する際は、まず仮想環境を作成・有効化し、その中でライブラリを管理するのが基本作法。

**チェックポイント**:
- なぜ仮想環境を使わずに、グローバルに`pip install`を続けるべきではないのですか？
- 新しいメンバーがプロジェクトに参加しました。その人が開発環境をセットアップするために渡すべきファイルは何ですか？そして、その人はどのコマンドを実行すべきですか？
- `pip freeze > requirements.txt` を実行する最適なタイミングはいつだと思いますか？
