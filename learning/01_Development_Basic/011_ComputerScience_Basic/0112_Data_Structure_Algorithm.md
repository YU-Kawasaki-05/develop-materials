# 第2章 データ構造とアルゴリズムの基本

## 🎯 この章で学ぶこと
- データ構造とアルゴリズムが、効率的なプログラミングの「両輪」であることを理解する。
- 配列、リスト、ハッシュテーブルなど、基本的なデータ構造の特徴と使い分けを説明できる。
- 探索やソートといった、基本的なアルゴリズムの目的と考え方を理解する。
- 「計算量」という概念に触れ、なぜそれがアルゴリズムの性能評価に重要なのかを把握する。
- 状況に応じて適切なデータ構造とアルゴリズムを選択するための、基本的な思考プロセスを身につける。

## 🤔 なぜ重要なのか
もしあなたが大量の蔵書を持つ図書館の司書で、目的の本を1冊探すことになったとします。本が何のルールもなく山積みにされていたら、見つけ出すのは至難の業でしょう。しかし、ジャンルごとに棚が分かれ、著者名のABC順に整理されていれば、探すのはずっと簡単になります。

この「本の整理方法」が**データ構造**であり、「目的の本を探す手順」が**アルゴリズム**です。

優れたエンジニアは、単にコードが書けるだけではありません。与えられた問題を効率的に解決するために、最適な「データの持ち方（データ構造）」と「処理の手順（アルゴリズム）」を設計できます。この知識は、アプリケーションの応答速度を劇的に改善したり、メモリ使用量を削減したりと、パフォーマンスに直接影響を与えます。AIにコーディングを任せる際も、どのデータ構造を使うべきか、どのようなアルゴリズムを適用すべきかを指示できなければ、質の高い成果物は得られません。これは、料理人が食材の特性を知り、最適な調理法を選ぶのに似ています。

## 📚 基礎概念の理解

### データ構造：情報を整理する「型」
データ構造とは、コンピュータのメモリ上でデータを効率的に扱い、整理するための「型」や「フォーマット」のことです。それぞれに得意なことと不得意なことがあり、問題の性質に応じて使い分ける必要があります。

#### 1. 配列 (Array)
-   **概念**: 同じ種類のデータが、メモリ上に連続して順番に並んだ構造。各データには通し番号（インデックス）が振られています。
-   **例え**: 番号が振られたロッカー。ロッカーの番号（インデックス）が分かっていれば、すぐに中身を取り出せます。
-   **長所**: インデックスを指定してのアクセスが非常に高速。
-   **短所**: 要素の追加や削除が苦手。途中の要素を削除すると、後ろの要素を全て前に詰める必要があります。

```javascript
// JavaScriptでの配列の例
const colors = ["Red", "Green", "Blue"];
console.log(colors[1]); // "Green" (インデックスは0から始まる)
```

#### 2. 連結リスト (Linked List)
-   **概念**: データが次のデータの場所（ポインタ）を数珠つなぎのように保持している構造。データはメモリ上にバラバラに存在できます。
-   **例え**: 宝探しゲーム。各宝箱に「次の宝箱のありか」が書かれた紙が入っているイメージ。
-   **長所**: 要素の追加や削除が高速。つなぎ変えるだけで完了します。
-   **短所**: 特定の要素にアクセスするには、先頭から順番にたどる必要があり、時間がかかります。

#### 3. スタック (Stack) & キュー (Queue)
これらはデータへのアクセス方法を制限した特殊なデータ構造です。

-   **スタック (LIFO: Last-In, First-Out)**
    -   **概念**: 最後に追加したデータが、最初に取り出される構造。
    -   **例え**: 積み上げられた皿。一番上に置いた皿から使います。
    -   **用途**: 関数の呼び出し履歴の管理（「元に戻す」機能など）。

-   **キュー (FIFO: First-In, First-Out)**
    -   **概念**: 最初に追加したデータが、最初に取り出される構造。
    -   **例え**: レジの行列。最初に並んだ人から会計します。
    -   **用途**: タスクの待ち行列、イベント処理。

```mermaid
graph TD
    subgraph スタック (LIFO)
        direction LR
        A[データ投入] --> B((1));
        B --> C((2));
        C --> D((3));

    end
    subgraph キュー (FIFO)
        direction LR
        F[データ投入] --> G((1)) --> H((2)) --> I((3)) --> J[データ取出];
    end
```

#### 4. ハッシュテーブル (Hash Table)
-   **概念**: キーと値のペアを保存するデータ構造。キーを元に「ハッシュ関数」という計算を行い、データの保存場所を高速に特定します。
-   **例え**: 巨大な辞書。単語（キー）さえ分かっていれば、ページ数（計算結果）がすぐに分かり、意味（値）を引けます。
-   **長所**: データの検索、追加、削除が非常に高速（平均的に）。
-   **短所**: データが順序通りに並んでいない。ハッシュ関数によっては性能が劣化することがある。
-   **別名**: 辞書(Dictionary)、連想配列(Associative Array)などとも呼ばれます。

```python
# Pythonでのハッシュテーブル（辞書）の例
user = {
    "id": 123,
    "name": "Taro Yamada",
    "email": "taro@example.com"
}
print(user["name"]) # "Taro Yamada"
```

### アルゴリズム：問題を解決する「手順書」
アルゴリズムとは、ある特定の問題を解決するための、明確で有限な手順や計算方法のことです。同じ問題でも、複数のアルゴリズムが存在し、その効率は大きく異なります。

#### 1. 探索アルゴリズム (Searching)
データ構造の中から、目的のデータを探し出す手順です。
-   **線形探索 (Linear Search)**: 配列の先頭から順番に一つずつ調べていく、最もシンプルな方法。データが整理されていない場合に有効。
-   **二分探索 (Binary Search)**: **ソート済みの**配列の中央値と目的の値を比較し、探す範囲を半分に絞り込みながら探索する方法。非常に高速。

#### 2. ソートアルゴリズム (Sorting)
データを特定の順序（昇順、降順など）に並べ替える手順です。
-   **バブルソート**: 隣り合う要素を比較して入れ替えていくことを繰り返すシンプルな方法。教育用によく使われるが、効率は悪い。
-   **マージソート**: データを細かく分割し、それぞれをソートしてから統合していく方法。効率が良い代表的なアルゴリズムの一つ。
-   **クイックソート**: ある基準値（ピボット）を選び、それより大きいグループと小さいグループに分割していくことを繰り返す方法。一般的に非常に高速。

## 💡 実践的な活用

### どのデータ構造をいつ使うか？
-   **シナリオ1**: アプリケーションのユーザーリスト（1万人）を管理し、ユーザーIDを指定して情報を即座に取り出したい。
    -   **最適な選択**: **ハッシュテーブル**。キー（ユーザーID）から値（ユーザー情報）をO(1)（ほぼ一瞬）で引けるため。配列で線形探索すると最悪1万回の比較が必要。
-   **シナリオ2**: テキストエディタの「元に戻す（Undo）」機能を実装したい。
    -   **最適な選択**: **スタック**。直前の操作（"文字入力", "削除"など）をスタックに積み、Undoが押されたら一番上の操作を取り出して実行する（例：「文字入力」のUndoは「削除」）。
-   **シナリオ3**: 音楽プレイリストで、曲を簡単に追加・削除・順序変更できるようにしたい。
    -   **最適な選択**: **連結リスト**。配列と違い、曲の追加や削除、順番の入れ替えが、前後の曲のリンクをつなぎ変えるだけで済み、高速に行えるため。

### ハンズオン：二分探索の威力を体感する
1から1,000,000までの数字の中から、ある1つの数字を当てるゲームを想像してください。

-   **線形探索の場合**: 「1ですか？」「2ですか？」...と順番に聞いていくと、最悪の場合100万回の質問が必要です。
-   **二分探索の場合**:
    1.  「500,000より大きいですか？」→ No
    2.  「250,000より大きいですか？」→ Yes
    3.  「375,000より大きいですか？」→ Yes ...
    このように、毎回探す範囲が半分になります。100万個のデータでも、たったの約20回の質問で答えにたどり着けます (2^20 ≒ 100万)。

この差が、アルゴリズムの力です。

## 🔍 深掘り：プロの視点

### 設計における考慮点：計算量
アルゴリズムの性能を客観的に評価する指標が**計算量 (Computational Complexity)**です。入力データのサイズが大きくなったときに、処理時間（時間計算量）や使用メモリ量（空間計算量）がどのくらいの割合で増えるかを示します。

-   **O(1) (定数時間)**: データ量によらず、常に一定時間。ハッシュテーブルの検索など。**最高**。
-   **O(log n) (対数時間)**: データ量が倍になっても、処理時間はわずかしか増えない。二分探索など。**非常に良い**。
-   **O(n) (線形時間)**: データ量に比例して、処理時間が増える。線形探索など。**普通**。
-   **O(n^2) (二乗時間)**: データ量が2倍になると、処理時間は4倍になる。バブルソートなど。**遅い**。
-   **O(2^n) (指数時間)**: データ量が少し増えるだけで、処理時間が爆発的に増加する。**最悪の部類**。

AIにコード生成を依頼するとき、「このリストをソートして」とだけ頼むと、非効率なO(n^2)のアルゴリズムが生成されるかもしれません。「O(n log n)のアルゴリズム（マージソートやクイックソートなど）を使ってソートして」と具体的に指示することで、パフォーマンスが劇的に向上します。

### 技術選択の判断基準：トレードオフを意識する
完璧なデータ構造やアルゴリズムは存在しません。常に**トレードオフ**の関係にあります。

-   **時間 vs. 空間**: 処理速度を上げるために、より多くのメモリを消費することがあります（例: 検索を速くするためのインデックスをハッシュテーブルで保持する）。逆に、メモリを節約するために、都度計算を行い、時間がかかることもあります。
-   **実装の容易さ vs. パフォーマンス**: クイックソートは高速ですが、実装がやや複雑です。データ数が少ないことが分かっているなら、実装が簡単なバブルソートで十分な場合もあります。

プロのエンジニアは、問題の制約（データサイズ、応答速度の要求、メモリ制限など）を考慮し、これらのトレードオフを理解した上で、最もバランスの取れた技術選択を行います。

## 📋 まとめとチェックポイント
- データ構造は「データの整理方法」、アルゴリズムは「問題の解決手順」。
- 基本的なデータ構造（配列、リスト、ハッシュテーブル等）にはそれぞれ得意・不得意がある。
- 基本的なアルゴリズム（探索、ソート）は、多くの問題解決の基礎となる。
- 計算量はアルゴリズムの性能を示す重要な指標であり、O(1), O(log n), O(n)などを理解することが重要。
- 常にトレードオフが存在するため、状況に応じた最適な技術選択が求められる。
