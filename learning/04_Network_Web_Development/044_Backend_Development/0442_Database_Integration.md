# データベース連携

## 🎯 この章で学ぶこと
- バックエンドアプリケーションとデータベースを接続する基本的な仕組みを理解する。
- ORM (Object-Relational Mapping) の役割と利点・欠点を学ぶ。
- 生のSQLクエリとORMの使い分けについて理解する。
- データベース接続プーリングの重要性を学ぶ。
- トランザクション管理の基本概念を理解する。

## 🤔 なぜ重要なのか
ほとんどのWebアプリケーションは、ユーザー情報、商品データ、投稿内容など、何らかのデータを永続的に保存する必要があります。その保管場所がデータベースです。バックエンドアプリケーションは、このデータベースと対話し、データの読み書きを行わなければなりません。

データベース連携は、料理における「食材の仕入れと管理」に例えられます。新鮮で質の良い食材（データ）を、必要な時に素早く正確に取り出し、調理（ビジネスロジック）に使うための重要なプロセスです。連携方法が非効率だと、アプリケーションの応答が遅くなったり、データの不整合が発生したりと、サービス全体の品質に直結する問題を引き起こします。堅牢で効率的なデータベース連携方法を学ぶことは、信頼性の高いアプリケーション開発に不可欠です。

## 📚 基礎概念の理解

### データベース接続の仕組み
アプリケーションがデータベースを操作するには、まず「接続（コネクション）」を確立する必要があります。これには通常、以下の情報が必要です。
- **ホスト名**: データベースサーバーのアドレス
- **ポート番号**: データベースが待ち受けているポート
- **データベース名**: 接続先のデータベース
- **ユーザー名/パスワード**: 認証情報

接続が確立されると、アプリケーションはそのコネクションを通じてSQLクエリを送信し、結果を受け取ることができます。

### ORM (Object-Relational Mapping)
- **概念**: プログラミング言語の「オブジェクト」と、リレーショナルデータベースの「テーブル」を自動的に対応付ける（マッピングする）技術です。これにより、開発者はSQLを直接書く代わりに、使い慣れたプログラミング言語の作法でデータベースを操作できます。
- **身近な例**: スマートフォンの連絡帳アプリを想像してください。一人ひとりの連絡先は「Person」というオブジェクトとしてプログラム内で扱えます。この「Person」オブジェクトを保存すると、ORMが自動的に裏側で`INSERT INTO contacts ...`のようなSQL文に変換し、データベースに保存してくれます。開発者はSQLを意識する必要がありません。
- **技術的詳細**: 主要なORMライブラリには、Pythonの`SQLAlchemy`、Javaの`Hibernate`、JavaScript/TypeScriptの`Prisma`や`TypeORM`などがあります。これらのライブラリは、データベースのスキーマからクラス定義を自動生成したり、その逆を行ったりする機能を提供します。

### 生のSQL (Raw SQL) vs ORM
- **生のSQL**: 開発者が直接SQLクエリを記述する方法。
    - **メリット**: 非常に複雑なクエリや、パフォーマンスが最重要視される場面で、最大限のチューニングが可能です。
    - **デメリット**: SQLインジェクションなどのセキュリティリスク管理が必要。データベースの種類（MySQL, PostgreSQLなど）が変わると、クエリの修正が必要になる場合がある（方言）。
- **ORM**:
    - **メリット**: 生産性が高い。コードの可読性が向上し、ビジネスロジックに集中できる。データベースの種類を抽象化してくれるため、移行が比較的容易。
    - **デメリット**: 自動生成されるSQLが非効率な場合がある。ORMの学習コストがかかる。ORMの機能範囲を超える複雑な操作は難しい。

## 💡 実践的な活用

### ハンズオン：ORMを使った基本的なデータ操作
- **課題**: Node.jsとPrisma（ORMの一種）を使い、新しいユーザーを作成し、データベースに保存する簡単な処理を実装します。
- **コードサンプル (TypeScript with Prisma)**:
```typescript
// prisma/schema.prisma (スキーマ定義)
model User {
  id    Int     @id @default(autoincrement())
  email String  @unique
  name  String?
}

// main.ts (アプリケーションコード)
import { PrismaClient } from '@prisma/client'
const prisma = new PrismaClient()

async function main() {
  // 新しいユーザーを作成
  const newUser = await prisma.user.create({
    data: {
      name: 'Alice',
      email: 'alice@example.com',
    },
  })
  console.log('Created new user: ', newUser)
}

main()
```
- **期待される結果**: このコードを実行すると、Prismaが裏側でSQLの`INSERT`文を生成・実行し、データベースの`User`テーブルに新しいレコードが追加されます。開発者はSQLを一行も書いていません。

### よくある落とし穴：N+1問題
ORMを使う際によく発生するのが「N+1問題」です。これは、1つの親データを取得した後、その子データを取得するために、子の数（N）だけ追加のクエリが発行されてしまう問題です。
- **例**: 10人のユーザー（`users`）とその投稿（`posts`）を一覧表示する場合。
    1. ユーザー一覧を取得する (1クエリ)
    2. 各ユーザーの投稿を取得するために、ユーザーごとに追加クエリを実行 (N=10クエリ)
    - **合計で1+N=11回のクエリ**が発行され、パフォーマンスが著しく悪化します。
- **対策**: ORMには通常、`Eager Loading`（`JOIN`を使って一度に読み込む）や`Batch Loading`といった、この問題を解決するための機能が用意されています。

## 🔍 深掘り：プロの視点

### データベース接続プーリング (Connection Pooling)
データベースへの接続・切断は、コストの高い（時間がかかる）処理です。リクエストごとに接続を確立していると、アプリケーションのパフォーマンスが低下します。
- **概念**: 事前に一定数のデータベース接続を確立しておき、「プール」に貯めておきます。アプリケーションはリクエストが来た際に、プールから既存の接続を借りて使用し、処理が終わったら返却します。
- **効果**: 接続確立のオーバーヘッドがなくなり、アプリケーション全体の応答性が向上します。ほとんどのWebフレームワークやORMライブラリは、接続プーリングの機能を内蔵しています。

### トランザクション管理
- **概念**: 「すべて成功するか、すべて失敗するかのどちらか」であるべき一連のデータベース操作をまとめた単位です。
- **例**: 銀行の振り込み処理。「Aさんの口座から1万円引く」処理と、「Bさんの口座に1万円足す」処理は、必ずセットで成功しなければなりません。途中でエラーが起きた場合、すべての操作を振り出しに戻す（ロールバックする）必要があります。この一連の処理がトランザクションです。
- **ACID特性**: トランザクションは、原子性(Atomicity)、一貫性(Consistency)、独立性(Isolation)、永続性(Durability)という4つの重要な特性（ACID）を持つ必要があります。

## 📋 まとめとチェックポイント
- バックエンド開発において、データベース連携は中核的な機能である。
- ORMはSQLを抽象化し生産性を高めるが、パフォーマンス上の注意点（N+1問題など）も存在する。
- 生のSQLとORMは、要件（パフォーマンス、生産性、複雑性）に応じて使い分けることが重要。
- 接続プーリングは、アプリケーションのパフォーマンスを維持するための必須テクニック。
- トランザクション管理は、データの整合性を保証するために不可欠な概念である。
